# specs/tracker/spec.md — Спецификация мини-трекера

## MUST
1. Добавление, удаление и переключение `done` реально изменяют данные в памяти приложения.
2. Название задачи после `trim()` должно быть непустым. Часы — число от 0,5 до 24 с шагом 0,5. Пустое значение часов не трактуется как ноль.
3. При ошибке валидации сообщение об ошибке отображается рядом с соответствующим полем, а введённые данные формы сохраняются.
4. Прогресс вычисляется как `round(100 × Σ hours(done) / Σ hours(all))`. Если задач нет — 0 %, без `NaN` и `Infinity`.
5. Фильтр влияет только на видимый список. Итоговые часы и прогресс считаются по всем задачам.
6. Интерфейс читаем на ширине 390 px, без горизонтального скролла. Все поля и кнопки имеют подписи.
7. Стартовый набор задач: «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`.

## SHOULD (необязательное улучшение)
- Сохранять задачи в `localStorage`.
- При недоступности хранилища показывать понятное сообщение и продолжать работу в памяти.

## Сценарии WHEN / THEN

### Стартовый пример
- GIVEN стартовый набор задач (8 ч всего, 2 ч выполнено)
- THEN итог = 8 ч, прогресс = 25 %.

### Сценарий 1 — фильтр «активные»
- WHEN включён фильтр «активные»
- THEN список показывает только невыполненные задачи
- AND прогресс остаётся 25 %.

### Сценарий 2 — невалидный ввод
- WHEN введено пустое название или пустые/отрицательные часы
- THEN задача не добавляется
- AND рядом с полем видна ошибка
- AND данные формы сохраняются.

### Сценарий 3 — все задачи удалены
- WHEN все задачи удалены
- THEN итог = 0 ч
- AND прогресс = 0 %.

### Сценарий 4 — отметка «Практики»
- WHEN задача «Практика» отмечена как выполненная
- THEN выполнено 6 ч из 8 ч
- AND прогресс = 75 %.
